# 加密事件驱动（金十快讯 → AI 判定 → 纸盘开仓）2026-09-25

> 状态：**代码/测试/页面/设置页全部完成，未部署**。
> 真数据端到端跑通过（抓取→识别→AI→行情源）；AI 用 DeepSeek 官方 `deepseek-flash`。

## 一、数据流

```
[抓取 60s] t.me/s/jin10light 公开预览页 → 只取 msg_id > 水位（首轮只记水位，绝不回填）
   ↓ 币种识别（中文别名 + 英文 ticker，且必须过"币安合约可交易集合"）→ 没有币种的直接丢弃
[AI 分析 5s] 一条消息一次请求（不跨消息合并）+ 并发池 4 → 利多/利空/中性/无关 + 依据 + 置信度
   ↓
[交易 10s] 利多→开多、利空→开空、中性/无关→不开 → trade_logic.open_paper_position（纸盘）
```

## 三、数据库（独立库 `db/crypto_event.db`）

```sql
crypto_event_raw    msg_id UNIQUE / ts(ISO UTC) / text / coins(JSON)
crypto_event_ai     event_id+coin UNIQUE / impact / reason / confidence / status / attempts / traded
crypto_event_trade  event_id / coin / position_id / side / ok / reason
crypto_event_meta   key-value（watermark_msg_id / last_poll_at / last_ai_at / ai_state）
```

**仓位不在这里** —— 走系统统一的 `trade_positions`（主库，`strategy='crypto_event'`），
跟 supertrend / onchain / alphafox 一样。所以**跨库不能 JOIN**，页面那条"该事件开的仓"是两次查询拼的。

## 六、实测结论（2026-09-25 真数据）

```
真抓 20 条 → 含币种 3~4 条 → 可交易集合 527 币
[0.9s] 「Sequans已清仓比特币，完全退出财库战略」→ BTC 利空 72     ← 中文别名认出来的（消息里没写 BTC）
[1.8s] 「QNT涨超38%，NEAR再涨17%」→ QNT 中性 78 / NEAR 中性 78   ← 一条消息两个币、一次请求两个判定
[1.0s] 「Bitget 空投 UNI」→ UNI 无关 95                            ← 噪音被正确归到"无关"，不开仓
```
- **单条 0.6~5.3 秒**（thinking/max；比 NVIDIA 托管版快了一个数量级）
- 全链路（事件发布→开仓）≈ **1.5 分钟**（抓取≤60s + AI≤5s + 交易≤10s）
- 事件密度：约 **50~60 条/天**含币种 → 配合 `event_daily_max=12` 会**上午就打满** ✗ 先跑几天看 `/crypto-event-ai` 里"未下单：…"的统计再调

## 七、踩过的坑（别重犯）

1. **推理模型 `max_tokens` 是"推理+正文"总预算**：`reasoning_effort=max` 实测烧 854 个
   推理 token → 预算 800 会把正文挤空（返回 `content=None`）→ 开思考时必须给 4000
2. **首轮绝不回填**：否则几百条历史 × 每条一次 AI + 一堆过期事件开仓
3. **只收录有币种的消息**：不认出的直接丢弃（水位照常推进），并打一行
   `未识别到币种，跳过：…` 方便定期 review 该补哪些中文别名
4. **页面缺 `<script>` 标签 → JS 当正文渲染（满屏乱码）**；且旧的检查器对"0 段 script"
   的页面**直接判通过（假绿灯）** → 已补断言 + 变异 M255 盯住
5. **设置页数字框清空时 `Number('')=0`** → 会把"置信度门槛"存成 0（门槛消失）→
   数字项一律用 `numOrUndef()`
6. 平台词表/夹具铁律照旧：夹具从真页面实抓裁剪（`extra/fixtures/jin10_sample.html`）
