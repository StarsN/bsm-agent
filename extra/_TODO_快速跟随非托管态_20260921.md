# 快速跟随 × 非托管态：纸盘不追平 + 实盘被砍回旧量

> 状态：**已定位根因、已用真引擎复现、修法已验证（含"只改一层不够"的实测）**；
> 用户 2026-09-21 决定**先不修**。改的时候照下面走。

## 现象

`取消托管（或已脱离）→ 交易员加过仓 → 我手动加过仓 → 点「⚡ 快速跟随」`：

```
[我手动→0.30 后] 纸盘=0.1（反推交易员 10） managed=0 | 记录=0.3 k=0.01 | 交易所=0.3
[快速跟随当轮]   纸盘=0.1（反推交易员 10） managed=1 | 记录=0.1 k=0.01 | 交易所=0.1
                 本轮交易所下单: [{'act':'close','qty':0.2}]   ← 手动加的 0.2 被卖掉
                 页面返回: {"action": "补齐"}                    ← 还谎报"补齐"
```

一次点击两个错：

1. **纸盘没追平**——按钮承诺的"补齐"没发生（纸盘仍反推交易员 10，实际 20）
2. **实盘被反向减仓**——对账目标按**旧交易员量**算（`10 × k(0.01) = 0.1`），交易所是 0.30 → 判"超了"就卖 0.2

## 影响范围（实测四态）

| managed | 快速跟随 | 说明 |
|---|---|---|
| 1 托管中 | ✅ 正常 | 纸盘本来就新鲜；且手动加的部分有归属闸门保护 |
| 2 恢复中 | ✅ 正常 | 守卫对它是放行的（`IN (1,2)`）；且通常下一轮就落定 |
| **0 取消托管** | ❌ **中招** | 0.30 → 0.10 |
| **3 已脱离** | ❌ **中招** | 0.30 → 0.10 |

## 根因

`alphafox_trade.quick_follow` 的"已有仓"分支（约 L926-932）：

```python
else:
    try:
        _align_our_position(trader_id, key, cv, params)   # ← 非托管态被守卫挡掉
    except _DataUnavailable as e:
        ...
    _set_managed(row["id"], MANAGED_ON)                    # ← 返回值被忽略，状态照样翻
```

`_align_our_position` 有**双层**守卫：

| 层 | 位置 | 条件 |
|---|---|---|
| Python | `alphafox_trade.py:626` | `_managed(pos) not in (MANAGED_ON, MANAGED_REATTACH)` → `return False` |
| SQL | `_ACT_GUARD_ALIGN`，函数里 **4 处** UPDATE 后缀 | ` AND IFNULL(managed,1) IN (1,2)` |

挡住 `managed ∈ {0,3}`（正好是非托管两态）→ 纸盘停在旧量 →
`_trader_qty_of(pp)` 反推出**旧交易员量** → 下一轮对账 `target = 旧量 × k` ≠ 交易所现状 → 真减仓。

**为什么 0/3 比托管中更危险**：托管中时"你手动加的那部分"有归属闸门保护

```
托管中：  记录=0.2（模型目标）、交易所=0.30 → "数量 ≤ 记录×1.25 = 0.25" 不通过
          → 判"混了手动仓" → 不越界减仓 ✅
取消托管：记录被**事实同步**成 0.3 → 参考量也变成 0.3 → 0.3 ≤ 0.375 通过 → 闸门失效 ❌
```

即：**取消托管期间"记录 ← 交易所"的同步，把归属闸门的参考量一起拉到了交易所现状**。

## 修法（完整版，两层一起放开）

```python
def _align_our_position(trader_id, key, cv, params, allow_unmanaged=False) -> bool:
    ...
    if not allow_unmanaged and _managed(pos) not in (MANAGED_ON, MANAGED_REATTACH):
        return False
    ...
    _guard = "" if allow_unmanaged else _ACT_GUARD_ALIGN     # 新增
    # 4 处 UPDATE： "... + _ACT_GUARD_ALIGN"  →  "... + _guard"
    #   （加仓 / 减到零 / 部分减 / 杠杆同步）
```

`quick_follow` 里 `_align_our_position(..., allow_unmanaged=True)`。

- **只改 Python 一层没用**——实测 `managed=0` 时带 `_ACT_GUARD_ALIGN` 的 UPDATE `rowcount=0`
  （`managed=1/2` 才是 1），纸盘照样不追平。
- **不要用"先翻状态再追平"代替**：那会制造「managed 已托管中、纸盘还是旧量」的窗口，
  对账线程扫到就按旧量下单（和 2026-09-21 修的 `on_reattach` 是同一类竞态）。
- `status IN ('OPEN','PARTIAL')` 必须保留（防写已平仓）。
- 语义自洽：快速跟随本来就是"用户显式要求现在按交易员当前量补齐"，且 `_align_our_position`
  只动纸盘（模拟层），不下真单。

## 修完之后的预期（不是"保现状"）

交易所会**补齐到「交易员当前量 × 原 k」**：本例 0.30 → **0.20**（原 k=0.01 × 20）。

- 修掉的是"按**旧量**算目标 → 砍到 0.10（旧规模）"
- 保留的是快速跟随的设计语义（M216 明确要求：不许像"恢复托管"那样按现状冻结，否则"点了等于没点"）

想看"保住手动加的仓"要用**恢复托管**（k 按现状重冻、零下单）——那条路径实测正常：

```
[恢复托管] 纸盘 0.1→0.2（追平到 20） | 记录 0.3 | k 0.01→0.015 | 交易所 0.30 零下单
[之后交易员 20→30] 纸盘 0.3 | 记录/交易所 0.30→0.45（按新 k 跟 +50%）
```
