## 四之七、第八轮：跟单实盘改「固定数量」口径（2026-09-17）

**起因**：用户发现 BTC 反复对账（真样本 09-16：`加一份 → 1 秒后减仓 0.001 → 随后又补仓 0.001`）。
根因：目标 = `份数 × 名义 ÷ **现价**` → 现价微动目标就跳 1 个 step，而容忍带(0.00053) < 1 step
→ 每次跳动都真成交。**修法（用户拍板的方案）**：

1. **开仓冻结"每份数量"** `lot_qty = 名义 ÷ 成交价`（存进 `exchange_orders_json`）→
   对账目标 = `份数 × 冻结每份数量` → **与现价无关** → "价格漂移修正"这类无意义成交彻底消失
2. **加仓量 = 新的量化目标 − 交易所现仓**（用冻结值算）→ 每次加仓正好落在目标上，
   不再"每次留个偏差、下一轮对账抹平"
3. 老记录没有 `lot_qty` → 按 `lot_notional ÷ entry_price` 折算一次并冻结（服务器上当时无活跃仓，
   这条只是保险）
4. 容忍带 step 下限（≥1.5×step）**保留**：现在防的是交易所取整/部分成交/手动改动
5. **顺带修一个本轮自己引入的真 bug**：冻结值"读-改-写"用了旧快照 → 把刚补写的
   `lot_notional` 冲掉；新增 `_load_fresh_orders()` 从库里重读最新再合并

**验证**：价格 +1%/+10%/+30% 全程 0 成交 · 卡量化边界抖 20 轮 0 成交（旧代码 30 笔）·
差 1 step 不补、差 10 step 补回 · 加仓在远离开仓价的现价下仍正好落在冻结目标 ·
`test_alphafox_live` 212 断言全绿 · 变异 **M204~M208** 全被抓住 · **M7 因新模型成结构性
no-op 删除**（与当初 M27/M32 同理），锚点 202/202 有效。

**行为变化**：每份的美元敞口随价格浮动（开仓时锁 200 U/份，价格涨这一份的美元值跟着涨）——
这就是"固定数量"的语义；名义仍保留在记录与页面（保证金/倍率展示用）。

## 四之八、第九轮：跟单实盘改「比例模型」+ ⚡ 快速跟随（2026-09-17，未部署）

**起因**：用户否掉"每份名义"（也否掉了上一节刚做的"固定每份数量"）——
规模应该跟着自己账户走：`k = 我的币安可用余额 ÷ 交易员保证金余额`，
**开仓那一刻冻结**；目标量 = `交易员当前量 × k`。交易员加多少我们加多少、
减多少我们减多少（比例天然一致），不再有"份"的概念。

### 1. 比例模型（`alphafox_live.py`）

- `available_balance_cached()`：可用余额，**60 秒内复用第一次读到的值**
  （用户语义"连开时用第一次的"，避免开一笔占一份保证金 → 下一笔比例变小）
- `_trader_qty_of(pp)` = 纸盘行反推交易员量 = **净持仓 ÷ k_qty**
  （`quantity − closed_qty`；系统口径里 quantity 是累计总量，减仓只累加 closed_qty）
- `_pos_ratio(lc, live, pp)`：记录里冻结的 k；老记录（份数模型写的）按
  "记录量 ÷ 交易员量"反推一次并**补写冻结**
- `_target_qty` = 交易员量 × k，按交易所 stepSize 量化
- 开仓冻结 `{"model":"ratio","k":…,"balance_ref":…,"trader_margin_ref":…}`
- 加仓 = 目标 − 交易所现仓；**减仓 = min(交易所现仓 − 目标, 我们记录 − 目标)**
  —— 后一项是关键：交易所可能混着你手动开的仓（同币同向合并），
  按总量减会把手动仓一起平掉
- 两条约束（`_funds_check`）：① 占用保证金 ≤ 可用余额（不满足只跳过加仓，
  减仓/平仓照跟，"加不动就不加，继续监控"）② 单笔上限 `max_notional`
  （0 = 不限）。挡下时写一次 `ratio_capped` 日志（原因没变不重复记）
- 归属判据换成：**杠杆一致（差 ≤0.5）且 数量 ≤ 参考量×1.25**
- `on_reattach`：解豁免 + **按交易所现状**冻结 k（不看旧记录量——同一窗口的
  手动改动会被按旧目标抹掉）

### 2. ⚡ 快速跟随（交易员卡片按钮）

`web.py` 探测线程缓存里已有该交易员快照 → `POST /api/alphafox/quick-follow`
（先 `dry_run` 预览 → 页面 confirm → 真跑）：

- 纸盘：无 → 建（k_qty 按当前保证金锁定）；有且归属本交易员 → 追平 + 置托管；
  别的交易员占用 → 跳过
- 实盘：`alphafox_live.quick_follow_live` 只过闸门**不下单**（用户需求 d：
  交易所杠杆 ≠ 设置杠杆 → 该币失败 + `quick_follow_blocked` 日志）；
  通过后解豁免 + 冻结 k，**由随后那一轮对账补到目标量**（只有一条下单路径）

### 4. 本轮抓到的真 bug（都是写测试/走查时才暴露的）

1. **🔴 `_trader_qty_of` 用累计量**：减仓后 `quantity` 不变、只累加 `closed_qty`
   → 交易员量看成没减 → 目标永不缩小 → **实盘跟着不减仓**。走查 C 段抓到。
2. **🔴 信号驱动的减仓会越界**：按 `交易所 − 目标` 减 → 把混在一起的手动仓
   一起平掉（真金白银）。改成"我们自己那份"，走查 S4 段抓到。
3. **🔴 残留记录收敛后 ex_row 快照未作废**：同一轮里平掉旧仓后又按旧数量算差额
   → 白跳过一轮（比例模型按目标量下单才暴露）。测试 39/43 抓到。
4. **🔴 REDUCE 日志里残留 `lots` 变量**（NameError 被 except 吞掉）：减仓成交了
   但日志永远不写。测试 49 抓到。
5. **🔴 资金约束漏在信号路径**：`_funds_check` 只在对账路径有，`apply_signal`

### 四之十、资金约束口径（用户 2026-09-18 澄清后重写）

### 四之十二、全局映射比例 α（2026-09-18，用户要控实盘风险）

用户需求：想按比例跟、但只跟一部分 → 加一个**全局映射比例**参数，缩小实盘敞口。

```
目标量 = 交易员当前量 × k × α        （k = 我的可用余额 ÷ 交易员保证金）
```

- 等价说法："我只用 α 比例的资金跟他"（虚拟余额 = 实际余额 × α）
- **只在"冻结新 k"时乘**：`apply_signal` 新开、`_mirror_missing` 补开新仓、
  `quick_follow_live` 的"不像我们的"参考量与新建资金预检
- **不乘**：`_pos_ratio`（老记录反推）、`on_reattach`（恢复托管）、
  `_mirror_missing` 的"认领已有仓"——那几条都是"目标==现状、零下单"，
  乘了会立刻把手里的仓砍成 α 折（用户没要求的减仓）。变异 **M225** 守这条
- 记录里冻结 `"alpha": α`（事后可核对这笔是几折跟的）；日志/打印带上
- 改 α **不动已有仓**（k 已冻结），与"改杠杆/改上限"语义一致
- 脏值/越界（≤0 或 >1）→ 回退 1.0（不因为配置表脏了就缩仓）
- 边界校验 **0.01~1.0**（>1 是放大风险，与参数目的相反 → 400 拒绝）。变异 **M227**

**顺带解决的痛点**：卡住"低杠杆跟高杠杆交易员"的条件是 `α × 他的有效杠杆
≤ 我的杠杆` —— α 就是通行证。实测熬鹰资本有效杠杆 6.57x、我们 5x：
α=1 需 368U（开不出）→ α=0.5 需 184U（开得出）。

测试：`test_alphafox_live` 第 70 段（α=0.5 半量 / 记录冻结 α / 改 α 不动已有仓 /
α 与资金约束联动 / 老记录反推不乘 α / 认领不乘 α / 脏值回退）；走查 **Q16**；
`_check_af_board` 第 7 段加接线与边界断言。变异 **M224~M227**，锚点 221/221。

### 四之十三、α 复查（2026-09-18）：低于最小下单量被"抬上去"的坑

复查 α 时发现：`exchange._round_qty` 是 `max(按 stepSize 取整, minQty)` ——
**不足 minQty 的量会被抬到 minQty，不是抹成 0**。于是：

- 映射比例越小 → 目标量越小 → **越容易开出"比 α 口径大几个数量级"的仓**
  （例：目标 1e-5 枚 → 抬成 minQty 0.01 枚 = 1000 倍）
- 原来只有对账路径有防护（容忍带的 minQty 下限），**信号路径没有**

修：新增 `_target_qty_raw()`（量化前的目标量），三处"要下单前"用它判
`本次要下的量 < minQty → 不下单并 log`：`apply_signal` OPEN/ADD（用**增量**
`raw − 现仓` 判）、`_mirror_missing` 补开、`quick_follow_live` 新建预检
（后者会如实回报"目标量低于交易所最小下单量"，不再谎报"新建"）。

**坑中坑**：第一版守卫拿**量化后**的目标去比 minQty —— 永远为假（量化已经把它
抬到 minQty 了），测试当场打脸。判据必须用**量化前**的值（变异 **M228** 守这条）。

测试段 70 追加 2 条（α 过小 → 不下单且如实回报；增量低于 minQty → 跳过加仓）。
变异 **M228**；锚点 **222/222**。

### 四之十四、认领/快速跟随的参考量改用**账户权益**（用户 2026-09-18 指出）

**问题**：`_looks_like_ours` 的参考量原来用**可用余额**算，可这两处的用途是判
"这笔交易所持仓**像不像我们开的**"——而**待判的那笔仓本身已经把保证金占掉了**
→ 参考量被它自己压小 → 仓越大（越可能是自家残留仓）越判"不像"，正好把要认领的
挡在门外（循环压缩）。用户实例：0.013 枚占掉 199U，可用从 278 压到 80.67 →
参考量 0.024 → 0.0067，判据上限 0.030 → 0.0084，自家仓被判"手动仓"。

**改法**（只动两处，其余四个用途不动）：

| 用途 | 分子 | 说明 |
|---|---|---|
| 开仓比例 k、资金约束 | 可用余额 | 不变（那是真能花的钱） |
| **`_mirror_missing` 认领判定 ④** | **账户权益** | 权益不依赖被判仓的大小，稳定上界 |
| **`quick_follow_live` 闸门 ⑤** | **账户权益** | 两处必须同口径，否则"页面说新建、对账又不认领" |
| `_align_qty` 减仓守卫 / CLOSE 兜底 | 记录量 / 只按杠杆 | 不变（判的是"像不像我们记录的那笔"） |

实现：`available_balance_cached()` 顺带把权益一起缓存（同一个 60s 窗口、同一次账户读），
新增 `account_equity_cached()`；两处闸门读不到权益时**回退可用余额**（行为退化成改动前）。
"可用+本仓占用"那种口径**不能**用——它随被判仓变大，任何大仓都会被认领。

用户案例效果：α ≥ 0.433 时，那笔 0.013 会被 ⑤ 放行、④ 认领（零下单，
k=0.0004246 按现状冻结，日志报"相当于 α=1.92"）；真手动大仓（500 枚 ≫ 上限 12.5）仍拒绝。

测试：`test_alphafox_live` 第 **71** 段（权益口径认领 / 可用口径会误拦 / 真大仓仍拒 /
快速跟随同口径）；变异 **M229/M230**；锚点 **224/224**。

### 四之十六、减仓不记已实现盈亏（走查场景 6 抓到）

### 四之十七、跟单 UNI 被误判平仓（2026-09-18，先落证据、后定方案）

**平台数据本来就常自相矛盾**（同一时刻实测）：`positions` 只有 1 条，而

**当前处置（用户 2026-09-18 拍板）：先加诊断日志，等下次出现再定修复方案。**

raw_n/raw_syms   原始 positions 数组（解析前）—— 空数组 vs 有条目但解析失败

- 注意反向风险：**漏跟真平仓比误平更危险**，不能一味加"不许平"的条件。
- `symbolCount` 不能当判据（实测 1 个仓时它也是 6）。

抓取方式：`grep AFLIVE-ANOMALY  logs/web/YYYYMMDD.log`。

**已知边界（非 bug，记着就行）**：
- 非托管期间用户**手动**加减仓 → `_reconcile_unmanaged` 只把记录对齐成事实、
  不算 realized（没有用户的成交价，宁可少算不编造）。
- `managed=3`（已脱离，恢复托管时发现交易员已无此仓）的仓**不再自动平**——
  纸盘与实盘都留着，需要你在实盘页手动平。
- 极窄窗口：取消托管期间手动平掉实盘 → 同一轮里立刻点"恢复托管"→
  记录已 CLOSED，对账不会自动重开（"这笔不再跟"的语义）。等交易员开新仓即可。
- CLOSE 兜底的参考量用的是**当前 α**；如果你后来把 α 调小，参考量会跟着变小
  （已开仓的量是按旧 α 的）→ 极端情况下可能判"不像"而留裸仓。要更宽松可以
  把参考量按 α=1 算（当前没那么做，保持与认领判定同口径）。
