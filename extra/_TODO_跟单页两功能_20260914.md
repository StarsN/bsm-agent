# 跟单托管页两个新功能 —— 2026-09-14（已实现，待部署）

> 用户确认的语义：**① 名义/杠杆在开仓那一刻冻结**，改设置只影响之后新开的跟单仓
> （全局设置也一样）；② 币种下拉 = 映射表 ∪ 交易过的币 + 手输；③ 杠杆本来就用我们的设置。

## 功能 1：跟单交易员持仓小卡片

- **数据共享**：探测线程本来就为"跟单中的交易员"每 15s 拉快照 → 新增模块级
  `_af_last_snap: dict[sid, {positions, polledAt, name}]`（web.py，`_af_polled` 旁），
  在取快照处无条件写入 → **零额外请求**，与雷达页是同一个快照
- **接口**：`/api/alphafox/board` 新增 `traders`：
  `{trader_id, label, stale, polled_at, pos_count, positions[], notional_sum, upnl_sum}`
  —— 缓存还没这份快照时 `positions=null` + `stale=true`（页面显示"等待探测"，**不谎报空仓**）
- **页面**：新增 panel「⑥ 跟单交易员持仓」，`.trd-grid` 小卡片（交易员名 + 持仓明细 +
  名义/浮盈汇总），点卡片跳 `/alphafox`

## 功能 2：币种设置（实盘每份名义/杠杆，留空=全局）

- **新表**（`alphafox_trade._TRADE_DDL`，库 `db/alphafox.db`，`init_db` 幂等建）：
  `alphafox_token_settings(token PK, live_notional, live_leverage, updated_at)`
- **冻结值存在 live 记录里**：`exchange_orders_json` 扩成
  `{"lots": N, "lot_notional": 50.0}`；杠杆用记录已有的 `leverage` 列（不需要改表）
- **取值链**（`alphafox_live`）：
  - `_eff_live_params(token, g_n, g_l)`：每币覆盖 → 回退全局
  - `_pos_lot_notional(lc, live_row, fallback)`：记录里冻结值；旧记录没有 → 用
    fallback 补写一次再冻结
  - 用在哪：`apply_signal`（OPEN 用生效值并冻结/ADD 与 REDUCE 用记录值/LEV 用记录杠杆）、
    `_align_qty`（目标量 = 份数 × 冻结名义 / mark）、`_mirror_missing`（补开用生效值并冻结）、
    `rebase_lots`（恢复托管重定档位用冻结值）
  - `sync_alphafox_live` 的逐币循环先解析每币生效值再传给 `_align_qty`/`_mirror_missing`
- **接口**：`POST /api/alphafox/token-settings` `{token, live_notional?, live_leverage?}`
  （留空 = 不设该项覆盖；两项都空 = 整行删除）；校验 token 字母数字、名义 0.01~1e6、杠杆 1~125
- **接口**：`/api/alphafox/board` 新增 `token_options`（映射表 ∪ 交易过的币）
  与 `token_settings`（全局值 + 每币覆盖 + **生效值** + has_position）
- **页面**：新增 panel「⑦ 币种设置」：表格（币种/名义/杠杆/生效值/编辑/清除）+
  新增行（`<datalist>` 下拉 + 手输）；文案写明"只对之后新开的仓生效"

## 行为变化（部署后要留意）

1. **改全局名义/杠杆不再调整已有实盘仓**（原来是下一轮对账就调到新目标）
   → 想调整已有仓只能手动或等新仓
2. 旧实盘记录（没有 `lot_notional`）首次对账会按**当时的生效值**补写一次并冻结
3. LEV 信号只把"记录里的杠杆"再设一遍（不再跟随设置改动）

## 复核（2026-09-14 晚，跑全流程走查）发现并修的问题

1. **🔴 流水水位不推进 → 加仓笔数被多算（我自己引入的）**：`_new_action_orders` 原本
   "只在有净加仓时标记已见" → "同一轮里加了又减（净额不变）"留下的单、以及跟单开始前
   就存在的历史单，会在**下一次真加仓**时被当成新增笔数 → 实盘多加几份。
   修：新增 `_seen_orders_advance()`，每轮（信号处理之后）无条件推进水位；计数函数只数不标。
   测试 56 段（197 断言）+ 变异 **M170** 锚定。
2. **`_looks_like_ours` 的形态判据漏用每币生效值/冻结值**：两处调用点（apply_signal 的
   CLOSE 兜底平仓、`_align_qty` 的减仓守卫）以前用**全局**名义 → 每币覆盖过的币会被
   判成"不像我们的"→ 记录丢失时不平、留裸仓。已改成该币生效值/记录冻结值。
3. **走查脚本自身的三个坑（不是生产 bug，记下来别再踩）**：
   - CLOSED 记录的 `quantity` 是历史值，不能拿去和交易所持仓比 → 只看活跃记录
   - 空快照要**连探两轮**才会被"快照异常 2 轮确认"消费掉，否则 `prev` 不清、下一笔
     新开仓不会发 OPEN 信号
   - 新键首见那一轮就开仓（不是下一轮），捕获信号要写在那一轮上

## 第二轮复核（2026-09-14 晚，用户要求再跑一遍）

4. **🟠 加仓/减仓口径不对称 → 份数单向偏高（已修）**：加仓按流水**笔数**还原，
   减仓按**净额**（一轮 1 条）→ 同一轮"加 3 笔 + 减 1 笔"会记成 3 份加仓、0 份减仓
   → 份数偏高（每出现一次高 1 份，长期累积 → 实盘目标量偏高）。
   修：按**净笔数**还原（`_want = |加仓笔数 − 减仓笔数|`，方向与持仓净变化一致时补齐；
   口径打架时保守只记主信号 1 条；净额减到零判 CLOSE 时不补减仓笔数）。
   走查 C 段（两笔减仓 → 2 份）、H 段（加 3 减 1 → 净 +2 份）固化；变异 **M171**。
5. **🟠 "交易所已无持仓"时 realized 记 0（已修）**：这种平仓是**别人下的单**
   （用户在币安手动平/强平），我们没有任何下单返回值 → 拿不到成交价。
   修：新增 `_paper_mark()`，按**纸盘最新现价**估算 realized（用户选了估算而非
   查 `userTrades`：零额外请求、不用猜哪笔是我们的）。测试 62 段；变异 **M172**。
   —— 要拿真实成交价只能查 userTrades，代价是额外接口调用 + 同币混手动单时难匹配。
6. 本轮复核确认没问题：`_close_exchange` 主体（executedQty 判成交、部分成交、
   realized 累加）、快照异常两轮确认、减到零全平、恢复托管按冻结值重定档位。

### 全流程走查 `_scenario_alphafox_cycle.py`（已加入 alphafox_live 组，31 断言）

A 开仓（冻结每份名义/杠杆）→ B 一个探测间隔内连加 3 笔（还原 3 条 ADD、实盘下 3 单、
份数=4）→ C 减一份 → D **手动平仓**（纸盘+实盘一起收尾、之后再加仓不复活）→
E 交易员平仓（快照异常两轮确认，只补一条未执行的 CLOSE）→ F 交易员新开一笔
（用**每币覆盖** 80/5 并冻结）→ G 减到零全平 + 收尾。每步验四项一致性
（纸盘 = 交易员量×k_qty、记录 = 交易所、记录 ≈ 份数×冻结名义/mark、冻结值不被改写）。
