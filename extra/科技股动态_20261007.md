# 科技股动态（2026-10-07）

新闻雷达（**不交易**）：金十快讯 → 拆条 → 三层识别 → Google 搜索 → AI 图解 → `/tech-news` 页面。
与两条事件管线的本质差别：**不做可交易白名单过滤**（华为/OpenAI 等未上市一样收），产出是"一张图看懂"而非交易信号。

## 一、链路

```
金十 TG（event_agent 同一抓取，抓一次三写）
        ├─► crypto_event.db / stock_event.db   （现有两条管线，未改动）
        └─► tech_news.db                        （新增）
                 │
   tech_stocks.split_items()    编号总结拆条（≥2 编号；圈号备用；全部保留不设上限）
                 │
   tech_stocks.identify()       三层兜底：公司(含未上市AI档/高管名) → 行业词 → 科技综合
                 │
   每个 (msg_id, item_no, stock_code) 三元组独立：
       Google News RSS 搜索（{标的+条目关键词} when:7d，串行+间隔+2次重试）
       → DeepSeek 图解 JSON（防编造：sources 必须出自搜索链接）
       → tech_news_ai 一行（status 0/1/2 独立重试）
                 │
   /tech-news 页面：分类 → 股票卡/行业卡/@科技综合 → 动态倒序 → 点开弹图解
```

## 二、拆条（真样本实测格式）

真样本来自服务器 stock_event_raw（msg 238210/238191/238174），踩过的格式坑：

- 编号内联排列："…达20%。 2. 三星电机…"
- 编号在小节标题后**重启**："重要新闻 1.…3.… 个股新闻 1.…"
- 编号**紧贴前文**："答记者问2. 自10月10日…"（正则不能要求前置空格）
- 嵌套圈号子项："9. 中东局势— ①…②…③…"（v1 不二次拆，防碎片化）

主编号正则 `(?<!\d)\d{1,2}[.、．](?!\d)`：防 37.3% / 2026. / 1.5亿 拆坏；
尾部小节标题碎屑（含抓取管道把 emoji 损坏的 é/ï 残字）用 `_TAIL_JUNK` 清洗。
**编号排版三种依序尝试**：阿拉伯数字（N. / N、）→ 圈号 ①②③ → 全角括号（N）——任何一种出现 ≥2 次即逐条拆。

## 三、三层识别（tech_stocks.py）

1. **公司层**：7 类 ~110 个别名（存储/代工/设备/芯片设计/消费电子/互联网/AI 前沿），
   含未上市（华为/OpenAI/DeepSeek/长江存储…）与**高管名映射**（黄仁勋→英伟达、苏姿丰→AMD、余承东→华为、库克→苹果）。
   长词优先（三星电机 ⊄ 三星）；歧义排除（三星堆/苹果丰收/库克群岛/高通胀/荣耀需语境）。
2. **行业层**：DRAM/NAND/HBM/存储 → `@存储`；光刻/刻蚀 → `@设备`；CoWoS → `@封装`；AI芯片/GPU/算力 → `@AI算力`。
3. **综合层**：芯片/半导体/晶圆/AI/服务器… → `@科技综合`（最宽兜底，防漏；噪音由用户后续剪词表）。

## 四、护栏理念：只控节奏，不丢消息

- 条目数/每条目标的不设内容上限；>30 条 / >10 标的仅打 WARN 日志（防拆分器跑飞/词典误伤的侦测，不拦截）
- 每日处理预算 200（`TECH_NEWS_DAILY_BUDGET`）：超出**只积压顺延**，永不丢弃；积压 >500 页面红字
- 每轮批次 5（`TECH_NEWS_BATCH_PER_ROUND`）+ 串行 1.2s 间隔（搜索礼仪）
- 搜索失败 → **退化**为"金十原文 + AI"（degrade=1，图中标注无外部来源）——功能不断档
- AI/搜索连续失败 3 次 → status=2（页面可一键重试，重新入队）
- AI 返回**结构整形**（数组/对象被答成字符串也强转，页面按数组渲染不崩）；sources 只收搜索链接
- 首轮只记水位不回填（部署后消息全收）；总开关关闭时不推进水位（重开自动补页内消息）
- 未命中条目存 meta（最近 20 条）供补词表

## 五、数据模型（db/tech_news.db）

```
tech_news_raw  msg_id(PK) / pub_ts / text(全文) / items_json[{no,text,stocks[]}]
tech_news_ai   (msg_id, item_no, stock_code) PK / stock_name / cat / status 0|1|2
               / attempts / degrade / search_json / summary_json{headline,tldr,points,numbers,impact,sources}
tech_news_meta watermark / first_run_at / last_poll_at / last_gen_at / daily_used:<date> / backlog / unmatched_samples
```

## 六、页面 /tech-news（导航：市场 ▸ 科技股动态）

- 状态条：已生成/待生成（积压）｜失败｜入库消息数｜上次抓取/生成
- 主体：按 8 个分类分组 → 每只股票一张卡（行业/综合为伪卡）→ 动态按时间倒序（标题=图解 headline，带 偏多/偏空/无来源 标签）；**未生成完的条目灰显「生成中」+ 原文前缀**（新消息无需等生成即可见到）
- 点开 → 图解卡片弹层：大字标题 + tldr + 编号要点 + 关键数字色块 + 影响标签 + 来源链接（可点）+ 金十原文折叠
- 失败区：可「重试」（/api/tech-news/retry）

## 十、已知限制

1. 嵌套圈号（①②③）不二次拆——同主题子点整体保留（防碎片化）
2. 综合兜底层较宽（AI/芯片/服务器等常见词）→ 会有一定噪音，观察后按 `unmatched_samples`/页面效果剪词表
3. 搜索源仅 Google News RSS（日本 IP 实测可用）；挂了自动退化，不会断档
4. 图是 HTML 图解卡片（非图片文件）；要 PNG 可用服务器已有 Playwright 截图，未做
5. **金十偶尔编辑已发布消息**（实测 238210：发布时是半导体纪要，后被改成 AI 纪要）：
   三条管线都按水位"只采一次"，编辑后的新内容不会重采，库里保留首版内容。属金十侧行为，暂不处理
6. Moonshot/Kimi 等英文短名依赖语境门（±12 字内需 AI 语境词）；实测该门已挡住"交易应用 Moonshot"误伤
