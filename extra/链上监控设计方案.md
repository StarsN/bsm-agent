# 链上监控（On-Chain Monitor）设计方案

## 概述

利用 OnchainOS CLI 工具，分两个阶段筛选代币：
- **Stage 1（吸筹检测）**：通过聚类分析发现"表面分散、实质集中"的代币，进入观察池，不投钱
- **Stage 2（启动准备）**：检测 LP 储备变化、Gas seeding、CEX staging 三个临门信号，晋级可建仓

页面路由：`/onchain`

---

## 数据源

全部使用 BSC 链（`onchainos token hot-tokens --chain bsc`），OnchainOS 提供以下命令：

| 命令 | 用途 | Stage |
|------|------|-------|
| `token hot-tokens` | 扫描热门代币，支持 top10%、holders、mc 筛选 | Stage 1 |
| `token cluster-overview` | 聚类概览：concentration、fundSourceSame%、newAddress% | Stage 1 |
| `token cluster-list` | 聚类详情：per-address isExchange/isContract/isKol | Stage 1 |
| `token advanced-info` | 代币详情：top10HoldPercent、riskLevel、tags | Stage 1 |
| `token liquidity` | LP 池储备量：tokenAmount | Stage 2 |
| `token holders` | 持币者详情：fundingSource、PnL | 辅助 |

## 核心设计

### Step 1 — 噪声剔除 + 有效集中度

OnchainOS 的 `cluster-list` 已做好地址聚类（同资金源 + 互转 + 同创建时间），每个地址标注 `isExchange`、`isContract`、`isKol`。

**做法**：读 cluster-list，过滤 `isExchange=true` 和 `isContract=true` 的集群，剩余集群持有量之和 = **有效集中度**。

不需要自己搭聚类引擎。

### Step 2 — 背离信号

真正值钱的不是"集中度高"，而是一个背离：
- `holderSameFundSourcePercent` > 30%（top 1000 holders 中有隐藏关联的占比高）
- `top10HoldPercent` < 40%（表面 top10 持仓看起来不集中）
- 两者同时成立 → 背离 → 进入观察池

### Step 3 — 吸筹斜率拐头

定期快照 `effective_concentration` 存入时序表。需要 >= 2 轮数据后才能对比：
- 有效集中度增速 < 0.5%（绝对值）→ "吸筹接近完成"
- 需等 Stage 2 信号确认才能动手

### Step 4 — Stage 2 三个临门信号

**信号一：LP 储备加速减少**
- `token liquidity` → 记录 `token_amount` → 比较最近 3-4 轮
- 最新减少速度 > 前一轮 × 1.5 → "加速减少"（80 分）
- 权重：50%

**信号二：新鲜钱包批量 seed gas**
- `cluster-overview` 四个条件打分：
  - `holderNewAddressPercent` > 2%（新地址占比）
  - `holderSameFundSourcePercent` > 35%（同源占比）
  - `holderSameCreationTimePercent` > 5%（同时创建占比）
  - `newAddressPercent` 在上升
- >= 3 分 = 强信号，2 分 = 弱信号
- 权重：35%

**信号三：CEX 充值地址 staging**
- `cluster-list` 中检测 `isExchange=true` 的新集群
- >= 3 个交易所集群且 > 5% 持有 → 强信号
- 权重：15%（方向不可判，降权）

**综合置信度** = LP × 0.50 + Gas × 0.35 + CEX × 0.15，>= 50% → 晋级 actionable

### Step 5 — 仓位按胜率（预留）

`onchain_pool.backtest_winrate` 列已预留，等历史数据积累后可做回测。

## 架构

### 文件清单

| 文件 | 作用 |
|------|------|
| `config.py` | `ONCHAIN_*` 8 个配置项 |
| `storage.py` | 4 张表 DDL + migration + 12 个 CRUD 函数 |
| `okx_source.py` | 5 个 OnchainOS CLI wrapper + `_safe_float` |
| `onchain_scanner.py` | 扫描器主逻辑 + 后台 daemon 线程 |
| `worker.py` | main() 启动扫描器线程 |
| `web.py` | `/onchain` 页面 + 4 个 API + 导航链接 |
| `settings page` | 链上监控阈值面板（4 个可调参数） |

### DB 表（4 张）

```
onchain_scanner_status    — 扫描器心跳（key, stage, round_number, ...）
onchain_snapshots         — 每轮快照时序（token, effective_concentration, divergence_score, ...）
onchain_lp_snapshots      — LP 储备时序（token, token_amount, ...）
onchain_pool              — 观察池/建仓池（token PK, pool_stage, confidence_score, ...）
```

### 扫描 Pipeline（每 4 小时一轮）

```
Step A: hot-tokens → 筛选 top10% < 40 的代币（最多 30 个）
Step B: cluster-overview + cluster-list → 过滤交易所 → 算有效集中度 → 写快照
Step C: fundSourceSame% > 30 且 top10% < 40 → 背离 → 入观察池
Step D: 超期清理（> 7 天未晋级移出）
Step E: [每 2 轮] Stage 2 检查 → LP/Gas/CEX → 置信度 >= 50% → 晋级 actionable
```

### 页面 Panels

```
Panel 1: 扫描状态 — 状态灯 / 轮次 / 已扫描 / 观察池 / 可建仓
Panel 2: 观察池 (Stage 1) — 代币 | 表层% | 有效集中度% | 资金同源% | 趋同 | 天数 | sparkline
Panel 3: 可建仓 (Stage 2) — 代币 | LP趋势 | Gas播种 | CEX上架 | 置信度% | 天数
```

### API 端点

```
GET /api/onchain/status              — 扫描器状态
GET /api/onchain/pool?stage=X        — 池成员（含 sparkline）
GET /api/onchain/snapshots?token=X   — 某代币快照历史
```

### 可配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 扫描间隔 | 4h | 全量扫描间隔 |
| 背离阈值 | 30% | fundSourceSame% > 此值触发背离 |
| 表层上限 | 40% | top10Hold% < 此值进入候选 |
| 观察天数 | 7d | 超期未晋级自动移出 |

## 可行性评估

### 能做好的

| 信号 | 数据源 | 可靠度 |
|------|--------|--------|
| 表面 top10% | hot-tokens / advanced-info | 高 |
| 有效集中度 | cluster-list 过滤交易所后 | 高 |
| 资金同源背离 | cluster-overview.holderSameFundSourcePercent | 高 |
| 集群趋势 | cluster-list.trendType（buy/sell） | 高 |
| LP 储备变化 | liquidity 时序对比 | 中 |
| Gas seeding | newAddress% + fundSource% 组合 | 中 |

### 受限的

| 信号 | 问题 | 对策 |
|------|------|------|
| CEX staging | 无法判断充币方向（布弹药 vs 出货） | 权重降至 15%，仅辅助 |
| Rug pull 检测 | cluster-overview.rugPullPercent 是模型分 | 用于负向过滤而非正向信号 |
| OnchainOS 聚类 | 偏向保守，多为单地址 cluster | 用 fundingSource 字段人工补验证 |

### 做不了的

- 实时链上交易追踪（无归档节点 / Dune API）
- Mempool 监控（无数据源）
- 跨链集中度分析（仅 BSC）
- CEX 充值方向判断（无交易所地址数据库）

## 对比测试记录

测试了 H、SYN、ALLO、BSB 四个代币：

| 指标 | H | SYN | ALLO | BSB |
|------|---|---|---|------|-----|
| 表面 top10% | 19.1% | 23.5% | 75.6% | 34.7% |
| top100% | 54% | 94%(假) | 99.6% | 98% |
| 同源/互转% | 56% | 无 | 42% | 41% |
| 判断 | 隐蔽关联在活动 | 假集中(交易所) | 真集中+吸筹 | dev卖光+聪明钱接盘 |

**BSB 最接近目标模式**：开发者清仓 + 聪明钱持续买入 + 41% 持有者隐藏关联 + 56% cluster buy 趋势。
