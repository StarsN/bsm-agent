# 美股/商品事件驱动（2026-10-02）

与「加密事件驱动」同构的第二条管线：**金十快讯 → 识别美股个股/商品标的 → AI 判利好/利空 → 纸盘开仓**。
用户定的边界：**美股个股 + 商品；不做指数/ETF**；抓取复用加密那条（同一频道只抓一次）；**独立数据库**。

## 一、总体架构

```
金十快讯 t.me/s/jin10light
        │  event_agent.scrape_once()：抓一次，写两个库
        ├────────► crypto_event.db      （原加密管线，未改动）
        └────────► stock_event.db       （新增，四张同构表）
                        │
              stock_coins.identify()  （中文名/英文名 → ticker，过双闸门）
                        │
              stock_ai_classify()     （DeepSeek，一次一条，利好/利空/中性/无关）
                        │
              stock_trade_once()      （纸盘，strategy='stock_event'，统一入口）
                        │
              /stock-events + /stock-event-ai 两页
```

- 进程：**复用 `event_agent.py`**（同进程 5 个线程：抓取 / 加密分析 / 加密交易 / 股票分析 / 股票交易）
- 两条管线各自 `try/except` 隔离：一条挂不拖累另一条；**抓取只做一次**（不重复打平台）
- AI 配置复用 `EVENT_AI_*`（模型/key/超时/thinking/并发）

## 二、标的识别（`stock_coins.py`）

**两道闸门**（缺一不可）：
1. 归一后的 ticker **必须在币安 TradFi 永续白名单**（`market.get_tradifi_symbols()`）——京东/百度/蔚来/波音/星巴克等未上市自动被挡
2. 一条消息最多取 `stock_event_max_tickers`（默认 3）个——"个股要闻整理"一条能含 5~7 个标的

**优先级**：① 带交易所后缀的代码（`英伟达(NVDA.O)`，最准）→ ② 商品词 → ③ 中文/英文公司名。
白名单覆盖：科技七雄/半导体/加密相关美股/消费医药金融/**港韩股**（腾讯/美团/快手/三星/SK海力士/现代/索尼）
+ 商品（XAU/XAG/XPT/XPD/CL/BZ/NATGAS/COPPER）。

**踩过的坑（都有测试/变异钉住；后两条是上线前用真数据演练抓出来的）**：
- `\b` 对中文失效（CJK 是 word 字符）：`AMD斥资`/`Coinbase比特币` 匹配不到 → 改用 **ASCII 字母 lookaround**
- 同一改动顺带救回重名保护：`MetaMask`/`metadata` 里的 `Meta` 不算（后面跟的是 ASCII 字母）
- `黄金交叉`/`黄金分割` 是技术分析术语 → 匹配商品前先剔除这些短语
- `超微` 有歧义（超微电脑=SMCI / 超威半导体=AMD）→ 只认全称
- 指数不映射（标普/纳指/道琼斯/QQQ/SPY 一律不出现在结果里）——"不做指数"是靠**不映射**实现，变异 M266 钉住
- **中文短名是常用词前缀**：实测宏观摘要「AI建设需求正在推高**通胀**」里的"高通"被当成 QCOM →
  `_NEG_NEXT` 下一个字排除表（高通→胀、现代→化），变异 M272 钉住
- **商品词重叠**：「布伦特**原油**」曾同时命中 布伦特→BZ 和 原油→CL（一处引用开两个高度相关的仓）→
  长词优先 + **区间去重**（同一处引用只算一次），变异 M271 钉住

**演练方式**：把本地 `stock_coins.py` 用 base64 送到服务器内存 exec，
对"金十最新一页 + 库里已存的真消息"跑识别（不改服务器文件、不写库）——两处 bug 都是这么抓到的。

## 三、AI 判定

- 档位：**利好 / 利空 / 中性 / 无关**（加密管线用"利多"，两条管线共用解析层，下单闸门各自过滤）
- prompt 要点：财报/指引/评级/监管/诉讼/回购/并购；**人物言行不算信号**（马斯克≠TSLA）；
  加密语境顺带提到的公司（交易所提币提到 Coinbase）通常判无关；"据悉/传闻"给低置信度
- **真 AI 冒烟实测（5 条真消息）**：财报不及预期→利空95、黄金创新高→利好85、OPEC增产→BZ+CL双利空85、
  Coinbase/BTC 语境→中性70 ✓；**纯行情播报**（"布伦特原油跌2%"）→ AI 判**中性**（理由：属数据描述）
  → 不会追价开仓 ✓（这是设计意图：只跟"新信息"，不追已走出的行情）；单条 1.2~4.5s ✓

## 四、纸盘交易（`strategy='stock_event'`）

6 条护栏（与加密事件同构）：开关 → 置信度门槛 → 新鲜度 → 同标的冷却 → 每日上限 → 一标的一活跃仓；
`traded` 标记保证一条判定只消费一次。仓位走系统统一入口 `trade_logic.open_paper_position`
（自动带 TP/SL/跟踪止盈）。

## 五、参数（设置页「📈 美股/商品事件驱动」+ config）

| 设置项 | 默认 | config |
|---|---|---|
| 策略开关 | 开 | `STOCK_EVENT_ENABLED` |
| 纸盘下单开关 | 开 | `STOCK_EVENT_TRADE_ENABLED` |
| 置信度门槛 | 75 | `STOCK_EVENT_MIN_CONFIDENCE` |
| 事件新鲜度（分钟） | 15 | `STOCK_EVENT_FRESH_MINUTES` |
| 同标的冷却（分钟） | 120 | `STOCK_EVENT_COOLDOWN_MINUTES` |
| 每日上限（笔） | 6 | `STOCK_EVENT_DAILY_MAX` |
| 每条消息最多标的 | 3 | `STOCK_EVENT_MAX_TICKERS` |
| 独立库路径 | db/stock_event.db | `STOCK_EVENT_DB_PATH` |

抓取间隔沿用 `event_poll_seconds`（两条管线同一循环）。

## 六、页面 / 接口

## 九、已知限制

1. **信号稀疏**：金十 crypto 频道里美股内容约 2 条/天 → 交易频率低（可换/加频道，见 `EVENT_CHANNEL`）
2. **TradFi 深度差**：美股/商品永续点差比主流加密大（参考超势 SNDK 的滑点教训）。
   **定仓口径**：走统一入口的**风险基数定仓**（按 ATR 止损距离反推数量，与加密事件同款）——
   股价/商品的 ATR% 越大 → 自动开得越小，所以没有"每笔名义"独立旋钮；
   要硬性压低单笔名义得改 `risk.compute_position_size`（本次没动）
   页面提示：AI 判定页有「🟢 美股盘中 / ⚪ 美股休市（美东 HH:MM）」——休市时段点差常变大，
   这不是闸门、只是提示（要改成"仅盘中开仓"再说）
3. **美股休市时段**：永续 24h 可交易但点差可能变大；暂不做"仅盘中"闸门（跑两周看数据再定）
4. **价格显示**：这条 WS 上 `markPrice`/`aggTrade` 不推流（连 BTC 也一样），价格走 `bookTicker` 的最优买/卖价
5. 不做指数/ETF（用户定）；港韩股按"股票类永续"一并收（不要可从 `NAME_MAP` 删行）
6. **短名前缀碰撞的低风险残余**（优步⊂优化步骤、思科、甲骨文、单字"铜"…）：未逐个加排除，
   命中后由 AI 判"无关"兜底（代价=多一次 AI 调用，不会产生坏单）；可按 `/stock-events` 的
   "最近未识别样本"观察后再往 `_NEG_NEXT` 里补
7. **`mode=live` 隐患（用户说先不管）**：`trade_logic.update_paper_positions` 里
   `self_mirrored` 白名单不含 `crypto_event`/`stock_event` → 全局切 live 时这两个纸盘策略的仓
   会被拿去和交易所比对（没有 → 标"实盘已平仓"）。现在 `mode=paper` 不触发
