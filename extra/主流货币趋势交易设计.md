# 主流货币超级趋势交易 — 实现设计方案（v5.4 定稿·已实现）

> 2026-09-05 定稿（取代旧文档《主流货币趋势交易.txt》）
> **状态：已实现并本地验证通过**（extra/test_supertrend_logic.py 26/26）
>
> 核心：监控币种**永远持仓**，跟随 15m 超级趋势轨道不断更新止损，扫损后按当前趋势重开。
> 本版只含**主要流程纸盘**，熔断/心跳告警/实盘适配后续再加。
>
> **架构**：
> 1. **开仓接入系统现有链路** —— 仓位写入主库 `trade_positions`（strategy='supertrend'），
>    由 auto_trader 现有 2s 循环（`update_paper_positions`）统一检测扫损平仓（同 onchain 仓位模式）
> 2. **策略自身表放独立数据库 `db/supertrend.db`** —— 监控币种/信号状态，与主库 schema 隔离
> 3. **参数设置页热生效** —— 线程始终创建，每轮读 trading_settings（开关/容忍%/金额/杠杆），
>    改完 ≤60s 生效无需重启
>
> **关键实现决策**：
> - trade_logic.py 只改 **1 处 5 行**（SL 平仓跳过复盘污染）；live 分支适配延后到实盘阶段
> - 移除平仓函数在 supertrend_strategy.py，不占 trade_logic
> - /strategies 页面展示：GROUP BY 天然出卡片 + enabled_map 运行状态 + 无仓位时补空行

## 二、数据库设计

### 2.1 新数据库 db/supertrend.db（策略自身表）

WAL 模式，连接/DDL/CRUD 封装在 `supertrend_strategy.py` 内部（同 onchain_scanner 自管 onchain.db 模式）。

```sql
-- 监控币种表（页面直接增删）
CREATE TABLE IF NOT EXISTS supertrend_tokens (
    token       TEXT PRIMARY KEY,
    status      TEXT NOT NULL DEFAULT 'ACTIVE',   -- ACTIVE / REMOVED
    added_at    INTEGER,
    removed_at  INTEGER
);

-- 策略状态表（每币最新信号，页面展示 + SL 更新去重）
CREATE TABLE IF NOT EXISTS supertrend_status (
    token           TEXT PRIMARY KEY,
    trend           TEXT,                 -- UP / DOWN（最新已闭合15m K线）
    upper_band      REAL,
    lower_band      REAL,
    last_candle_ts  INTEGER,              -- 最新已闭合K线时间戳(ms)，SL 更新去重用
    last_sl         REAL,
    last_price      REAL,
    state           TEXT,                 -- HOLDING / FLAT
    updated_at      INTEGER
);
```

### 2.2 主库 trade_positions（仓位，复用现有表）

仓位直接写主库现有 `trade_positions` 表，`strategy='supertrend'`、`mode='paper'`，
字段对齐现有结构（实现时按实际 schema 填写；tp1_price/trailing_stop_price 置 NULL，
现有 TP/跟踪止盈分支天然不触发）。页面"扫损重开历史"读 CLOSED 记录。

## 三、核心状态机（主要流程）

```
             ┌────────────────────────────┐
             │  无持仓（加入监控 / 被扫损后）│
             └──────────────┬─────────────┘
                            │ 超势线程下轮（≤60s）：
                            │ 闭合K线数据新鲜（≤20分钟）
                            │ 立即按当前 15m 趋势市价开仓
                            ▼
             ┌────────────────────────────┐
             │  HOLDING 持仓中             │
             │  SL = 持仓侧轨道 ± 容忍     │
             └───┬───────────────────┬────┘
 系统 2s 链路      │                   │ 超势线程：每根新闭合 15m K线
 update_paper_    │                   │ SL 只朝有利方向更新：
 positions 查价   │                   │   多：下轨道×(1−容忍%) 只上移
 触及 SL          │                   │   空：上轨道×(1+容忍%) 只下移
     ▼            │                   │   → UPDATE stop_loss_price
 平仓（跳过       │                   │      WHERE id=? AND status IN ('OPEN','PARTIAL')
 journal/归档）   │                   └──► 回到循环
     ▼            │
 无持仓           │
     └────────────┴─────────────────────────────┘
```

**"插针扫损→重开原方向" 与 "反转扫损→开反向仓" 是同一条规则**：
无持仓 → 按最新闭合K线趋势开仓。趋势还是 UP 就再开多（插针），趋势变 DOWN 就开空（反转），
线程不需要区分这两种情况。

**SL 公式**（容忍默认 1.0%，按轨道价百分比）：
- 做多：SL = 下轨道 × (1 − 容忍%)。例：下轨道 900 → SL = 900 × 0.99 = 891
- 做空：SL = 上轨道 × (1 + 容忍%)

**成交模型（纸盘）**：
- 开仓：按 `market.get_mark_price()`（币安标记价，与 SL 检测同一价格基准）
- 扫损平仓：SL 价 × 滑点系数（复用现有 `TRADING_STOP_SLIPPAGE_PCT`）
- 移除平仓：按标记价市价
- 盈亏：由现有平仓链路统一计算（与其他策略一致）

## 四、超势线程主循环（每 60s 一轮）

```
┌── supertrend_loop() 启动 ──────────────────────────────────────┐
│  建表（IF NOT EXISTS）+ 种入默认币种（INSERT OR IGNORE 幂等）    │
│  print("[supertrend] 已启动")                                  │
└──────────────────────────────┬────────────────────────────────┘
                               ▼
        每轮：conn_st = supertrend.db；conn_main = 主库
        读 trading_settings（enabled/容忍/金额/杠杆，热生效）
                               ▼
                    ┌─────────────────────┐
                    │ supertrend_enabled?  │──False──► sleep(60) 回到循环头（空转）
                    └─────────┬───────────┘
                              │ True
                              ▼
              ┌─ A. 清理已移除币种持仓（安全网）─┐
              │   tokens WHERE status='REMOVED' │
              │   主库若还有该币 OPEN 仓 → 平仓   │
              │   (reason='REMOVED'，幂等)       │
              └──────────────┬─────────────────┘
                             ▼
              ┌─ B. 遍历每个 ACTIVE 币种（独立 try/except）─┐
              ▼                                           │
   ┌───────────────────────────┐                          │
   │ 1. OKX 指标接口（15m）      │  失败→跳过该币            │
   │    → 已闭合K线 trend/上下轨道 │  （安全：SL不动，持仓仍   │
   │    → 写 supertrend_status  │    受系统 2s 链路保护）   │
   └───────────┬───────────────┘                          │
               ▼                                          │
   ┌───────────────────────────┐                          │
   │ 2. market.get_mark_price   │  失败→跳过该币            │
   │    → 写 last_price        │                          │
   └───────────┬───────────────┘                          │
               ▼                                          │
   ┌──── 查主库该币该策略任意方向 OPEN 仓 ────┐             │
   │ 有持仓                    │ 无持仓        │            │
   ▼                          ▼               │            │
 ┌──────────────┐  ┌────────────────────┐    │            │
 │ 新闭合K线?    │  │ 数据新鲜(≤20分钟)?  │    │            │
 │ 是→算新SL    │  │ 是→开仓            │    │            │
 │   只朝有利   │  │   INSERT 主库       │    │            │
 │   方向UPDATE │  │   趋势UP→开多       │    │            │
 │ 否→不动      │  │   趋势DOWN→开空     │    │            │
 │              │  │ 否→保持空仓        │    │            │
 └──────┬───────┘  └────────┬───────────┘    │            │
        └───────────────────┴────► 下一币 ────┘            │
                             ▼                            │
                 sleep(60 - 本轮耗时) 回到循环头 ────────────┘
```

**开仓细节**（`_open_position`，代码核实后的完整字段清单）：
- 前置检查：`storage.trade_has_active(main_conn, token, "supertrend")`
  （该函数无 side 过滤 = 单币单仓；线程是唯一开仓者，无并发开仓）
- 按当前趋势方向、标记价市价、固定名义金额 INSERT 主库 trade_positions
- **NOT NULL 字段必须填全**（trade_positions schema 核实）：
  `token` / `symbol`（= `f"{token}USDT"`）/ `side` / `status`（'OPEN'）/
  `mode`（'paper'，**显式写死，与全局 TRADING_MODE 无关**）/
  `margin_amount`（= notional/leverage ≈ 16.67）/ `leverage`（3）/
  `notional`（50）/ `quantity`（= notional/entry_price）
- `entry_price`/`current_price` = 标记价；`highest_price` = entry（多）/
  `lowest_price` = entry（空）；`tp1_price`/`tp2_price`/`trailing_stop_price` = NULL
- `open_reason` = "超级趋势 15m UP/DOWN 开多/开空"；`advice` = "跟随15m超级趋势：止损 @ $xx（无止盈）"
- `strategy` = 'supertrend'；用 `storage.trade_position_insert()`（唯一索引冲突返回 False，天然防同向重复）
- **SL 更新（`_update_sl`）不用 `storage.trade_position_update`**（它无状态条件）：
  线程用原生 SQL `UPDATE trade_positions SET stop_loss_price=? WHERE id=?
  AND status IN ('OPEN','PARTIAL')`，防写入已被 auto_trader 平掉的 CLOSED 行

## 五、trade_logic.py 适配（仅 1 处，约 5 行）

**代码核实结论（2026-09-05 通读实际代码）**：
- `update_paper_positions(conn)` 对**所有策略**仓位统一处理（无 strategy 过滤），
  supertrend 仓位自动获得 2s 级 SL 检测 → **开仓/持仓管理零改动，auto_trader.py 零改动** ✓
- tp1/tp2/跟踪止盈分支对 NULL 天然不触发（代码都是 `tp1 > 0 and ...` 判断）✓
- 价格链路 `_position_price()`：realtime≤5s → `get_mark_price()`（自动补 USDT 后缀）→
  旧缓存兜底，零改动 ✓
- `trade_has_active(conn, token, strategy)` **不带 side 过滤**，正好用作单币单仓检查 ✓
- 纸盘阶段 `mode=='live'` 分支不会执行（全局 TRADING_MODE=paper），
  **live 分支适配延后到实盘阶段**（实盘前必须做：否则 live 模式下
  纸盘仓位会被"实盘已平仓（交易所无此持仓）"逻辑 2 秒内误平仓，trade_logic.py:978-1017）

**唯一必须改的地方**：SL 平仓分支（trade_logic.py:1130-1168）对
`strategy=='supertrend'` 跳过 4 个复盘污染点：

```
if stop_triggered:
    is_supertrend = pos.get("strategy") == "supertrend"
    ...
    if realized < 0 and not is_supertrend:          # ← 跳过 1：亏损归档
        _archive_stop_loss(...)                      #   (line 1142)
    ...（平仓 UPDATE 本身照旧执行，不动）...
    if not is_supertrend:                            # ← 跳过 2/3/4：重行情调用 + journal
        _cs_snap = get_market_snapshot(...)          #   (line 1156)
        _cs_analysis = analyze_signals(...)          #   (line 1157)
        storage.journal_add_close(...)               #   (line 1159)
    if pos.get("strategy") == "onchain":             # 不动（onchain 专属）
        _archive_onchain_pool(pos["token"])
    continue
```

**为什么这 5 行必须改**：supertrend 每次扫损都会走这个分支。若不跳过：
- `journal_add_close` 把机械扫损写进 agent 复盘数据源（journal 表）→ 污染复盘统计
- `_archive_stop_loss` 写亏损归档 → 污染失败样本统计
- `get_market_snapshot(heavy=True)` 每次平仓拉币安重行情数据 → 拖慢 2s 主循环
平仓记录本身留在 trade_positions，页面历史直接读，不受影响。

**其他策略仓位：逻辑零改动。** trailing 分支（line 1220-1255）不用改——
supertrend 无 tp2/trailing（NULL），`tp2_done` 永远 False 不会进入。

## 六、添加/移除币种流程

### 添加币种（页面 → 开仓 ≤ 60s）

```
用户在 /supertrend 输入 "BTC" → 点击 [添加监控]
        │
        ▼
POST /api/supertrend/tokens  {"token":"BTC"}
        │  校验：大写规范化、非空
        ▼
后端双重验证：
  ① OKX 指标接口（BTC-USDT-SWAP, 15m）有数据 → 否则 400「无 OKX 永续合约数据」
  ② market.get_mark_price(token) 有价格 → 否则 400「无币安标记价（扫损检测依赖）」
        │
        ▼
写 supertrend.db：不存在 → INSERT；已存在(REMOVED) → UPDATE status='ACTIVE', removed_at=NULL
        │
        ▼（超势线程下个 60s 周期）
线程读到新币 → 主库无 OPEN 仓 → 数据新鲜 → 按当前 15m 趋势市价开仓
（INSERT 主库 trade_positions，strategy='supertrend'）
```

### 移除币种（页面 → 立即平仓）

```
点击卡片 [移除监控] → 弹确认「将立即平仓该币持仓」
        │
        ▼
DELETE /api/supertrend/tokens/BTC
        │
        ▼
① UPDATE supertrend_tokens SET status='REMOVED', removed_at=now
② 查主库该币该策略 OPEN 仓 → supertrend_strategy.close_supertrend_position(reason='REMOVED')
   （幂等：若系统 2s 链路恰在此时扫损平仓，rowcount=0 静默跳过）
        │
        ▼（线程下轮安全网）
线程清理步骤发现 REMOVED 币种还有 OPEN 仓 → 再平一次（通常 no-op）
```

## 八、配置项（设置页 4 键热生效 + config 常量）

**设置页参数（trading_settings，热生效）**：

| 键 | 默认值来源 | 说明 |
|---|---|---|
| `supertrend_enabled` | `SUPERTREND_ENABLED=True` | 总开关。线程每轮读取：False → 空转不交易（不拉OKX不开仓不更新SL）；True → 恢复。**系统 2s 扫损保护不受开关影响**（已有持仓永远被保护，关掉后扫损自然退出且不再重开 = 优雅停止） |
| `supertrend_sl_tolerance_pct` | `SUPERTREND_SL_TOLERANCE_PCT=1.0` | 容忍%（轨道价百分比） |
| `supertrend_notional_usd` | `SUPERTREND_NOTIONAL_USD=50.0` | 每笔名义金额 |
| `supertrend_leverage` | `SUPERTREND_LEVERAGE=3.0` | 杠杆（margin = notional/leverage） |
| `strategy_initial_supertrend` | `STRATEGY_INITIAL_SUPERTREND=1000` | 策略独立账户初始金额（/strategies 账户统计） |

**config.py 常量（不进设置页）**：
- `SUPERTREND_TOKENS = ["BTC","ETH"]` —— 首次种入默认币种（幂等，移除过的不会复活）
- 以上 4 个常量仅作为 trading_settings 默认值来源

**storage.py 改造 3 处**（trading_settings 体系接入）：
1. `trading_settings_defaults()` —— 加 4 个默认值

## 九、接口调用与限频

| 调用方 | 接口 | 频率 | 用量（2币） |
|---|---|---|---|
| supertrend 线程 | OKX 指标 `aigc/mcp/indicators` | 每币每 60s 1 次 | 2 次/分 |
| supertrend 线程 | 币安 `premiumIndex` 标记价 | 每币每 60s 1 次 | 2 次/分 |
| 系统 2s 链路（现有兜底） | 币安 `premiumIndex` 标记价 | 每币每 2s 1 次 | 60 次/分 |
| web API 添加验证 | OKX 指标接口 | 用户手动操作 | 忽略不计 |

限频：OKX 指标 5 次/秒/IP；币安 premiumIndex 权重 1。10 个币以内都安全。

**指标接口细节**（已验证）：

```
POST https://www.okx.com/api/v5/aigc/mcp/indicators
Body: {"instId":"BTC-USDT-SWAP",
       "timeframes":["15m"],
       "indicators":{"supertrend":{"returnList":true,"limit":2}}}
```

- 返回升序，最后一根是**正在形成**的K线，倒数第二根是**已闭合**K线；
  取已闭合 = 用确定性 ts 定位：`closed_ts = (now//900000)*900000 − 900000`（毫秒），
  找不到回退取倒数第二根
- `trend` 直接给 UP/DOWN；轨道用 `upperBand`/`lowerBand`
- **坑**：带 `paramList:[10,3]` 返回空数组 → 必须省略（服务端默认 10,3）
